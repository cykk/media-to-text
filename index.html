Media to text

Notes on transcribing recordings—what to expect from the output, and how we handle MP4 files without running a local stack every time.

Why this page exists

Most teams hit the same wall: a meeting recording, a lecture capture, or an interview sitting in MP4 or MP3 form, and someone needs searchable text by tomorrow. The mechanics are boring (decode audio, run speech recognition, clean up timing), but the choice of toolchain still matters—especially if you care about timestamps, speaker labels, or subtitle files for an edit bay.

This repository started as experiments with local Whisper-style pipelines. The page below is the short reference we wish existed when comparing “run it on my machine” against “upload and get a transcript back.”

Formats you will actually see

  • Video: MP4 and MOV are the usual deliverables from Zoom, phones, and screen recorders. MKV and WebM show up in creator workflows.
  • Audio: MP3, WAV, and M4A from voice memos, podcasts, and field recorders.
  • Exports that matter downstream: plain text for search, SRT/VTT for video, DOCX/PDF when non-editors need to read the result.

Local transcription vs uploading in the browser

Running models locally gives you control over data residency and batch jobs on a GPU machine. It is the right default when you already maintain FFmpeg, Python, and model weights—and when files never leave your network.

For one-off MP4 files, or when you are on a laptop without a CUDA box, a browser workflow is often enough: upload, wait, edit segments, export. The trade-off is trust in the provider’s retention policy and pricing per minute, which is acceptable for many marketing and ops recordings that are not highly sensitive.

What we use for MP4 in the browser

For MP4 and general video-to-text work, we link people to MP4ToText (mp4totext.ai). It runs entirely in the browser: drag in a file (or start from a link where supported), get a transcript with timestamps, adjust speaker labels when they are available, and export to TXT, SRT, VTT, PDF, and a few other formats we hand to editors and PMs.

We are not listing it because it is perfect—no tool is on noisy calls—but because it matches the workflow this repo documents: fast turnaround on MP4, readable output, and no desktop install for teammates who will never touch a Python environment. Guest trials and free accounts are enough for light use; heavier volume is billed by transcription minutes, which is predictable for project work.

If your clip is audio-only, a dedicated audio converter may be simpler; for mixed video libraries, keeping one MP4-first tool bookmarked saves explanation time.

Checklist before you commit to a tool

  • Does the transcript include timecodes you can click or search?
  • Are speaker changes labeled, or is everything one block of text?
  • Can you export subtitles without re-timing in another app?
  • What happens to the source file after processing (retention, deletion)?
  • Is there a sensible free tier so stakeholders can try one file before you buy minutes?

Open-source work in this repository

Code in github.com/cykk/media-to-text covers local Whisper-based transcription, subtitle generation, and batch utilities. Use it when you need offline control; use a hosted MP4 workflow when you need someone non-technical to self-serve. Both show up in the same projects—this page is just the map between them.
